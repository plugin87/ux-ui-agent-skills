# ใช้ ux-ui-agent-skills ยังไง — ฉบับภาษาไทย

เล่าสั้นๆ ว่ามันคืออะไร เข้าได้กี่ทาง และทางไหนเหมาะกับคุณ

ภาษาอังกฤษอยู่ที่ [INSTALL.md](INSTALL.md)

---

## มันคืออะไร

ชุดความรู้ด้านดีไซน์ที่เอเจนต์ AI อ่านแล้วทำตามได้ บวกกับ **เครื่องมือตรวจ 52 ตัว**
ที่วัดผลงานจริงว่าถูกต้องตามหลักหรือไม่

เครื่องมือตรวจคือหัวใจ ของอย่างอื่นบอกได้ว่า UI ที่ดีเป็นยังไง
แต่น้อยมากที่บอกได้**หลังทำเสร็จ**ว่าปุ่มที่คุณเพิ่งทำ คอนทราสต์ตอนเอาเมาส์ไปชี้
เหลือ 3.9:1 ซึ่งไม่ผ่านมาตรฐาน

## 1. Claude Code — ครบที่สุด

```
/plugin marketplace add plugin87/ux-ui-agent-skills
/plugin install ux-ui-agent-skills@ux-ui-agent-skills
```

ทางนี้ทางเดียวที่ได้ของที่ **บังคับได้** ไม่ใช่แค่ขอ

- **25 skills** โหลดเองตามงาน ขอให้ออกแบบหน้าจอ มันโหลดตัวที่ทำเรื่องนั้นมาเอง
- **3 hooks** ที่ทำงานโดยไม่สนว่าโมเดลจะจำได้หรือเปล่า — ห้ามเขียนค่าตายตัว
  ห้ามใส่ emoji ทุกครั้งที่บันทึกไฟล์ และห้ามจบงานที่แก้ UI แล้วไม่ได้วัดอะไรเลย
- **ตัววิจารณ์** ที่รันแยก context ไม่เห็นบทสนทนาที่ผลิตงานชิ้นนั้น

ติดตั้งเสร็จก็สั่งงานได้เลย ถ้า skills ยังไม่ขึ้นให้เริ่ม session ใหม่

## 2. Codex, Cursor, Copilot — ใช้ไฟล์กลาง

```bash
cd โปรเจกต์ของคุณ
npx ux-ui-agent-skills init --agent codex
```

สร้างไฟล์ `AGENTS.md` ไว้ที่รากโปรเจกต์ — เป็นมาตรฐานเปิดที่เครื่องมือราว 25 ตัว
อ่านได้โดยไม่ต้องตั้งค่าอะไร พร้อม token, สเปกคอมโพเนนต์, ดีไซน์ซิสเต็ม 138 ชุด
และ **เครื่องมือตรวจครบทั้ง 52 ตัว**

มันจงใจ**ไม่**สร้างโฟลเดอร์ `.claude/` เพราะ skills กับ hooks เป็นกลไกของ Claude Code
ถ้าใส่มาก็เป็นไฟล์ตายๆ

**สิ่งที่เสียไป พูดกันตรงๆ:** ไม่มี hook

บน Claude Code มีกฎ 3 ข้อที่บังคับใช้โดยโมเดลเลือกไม่ได้ ทางนี้ทุกกฎกลายเป็น
"คำขอ" และเครื่องมือตรวจจะทำงานต่อเมื่อคุณสั่งเท่านั้น **การสั่งรันจึงเป็นตัวตัดสิน
ว่าของชุดนี้จะมีประโยชน์หรือไม่**

อยากได้ทั้งสองแบบ:

```bash
npx ux-ui-agent-skills init --agent both
```

## 3. MCP — ให้ client ไหนก็รันเครื่องมือตรวจได้

```bash
claude mcp add ux-ui-gates -- npx -y --package=ux-ui-agent-skills ux-ui-mcp
```

> **`--package=` ห้ามลืม** ชื่อ package บังเอิญตรงกับชื่อคำสั่งตัวหนึ่ง
> ถ้าพิมพ์ `npx -y ux-ui-agent-skills ux-ui-mcp` มันจะไปรันตัวติดตั้งแทน
> แล้วพ่นหน้าช่วยเหลือออกมา ทำให้ client เชื่อมต่อไม่ติด

ได้ 6 เครื่องมือ

| เครื่องมือ | ทำอะไร |
|---|---|
| `list_gates` | ดูว่ามีตัวตรวจอะไรบ้าง แต่ละตัววัดอะไร |
| `run_gate` | สั่งตรวจทีละตัว ได้ผลดิบๆ กลับมา |
| `review_ui` | ตรวจทุกตัวที่เกี่ยวข้องทีเดียว |
| `get_doctrine` | ขอหลักการเขียนดีไซน์ แยกตามหัวข้อ |
| `get_design_system` | ขอสเปกดีไซน์ซิสเต็ม 1 ใน 138 ชุด |
| `get_tokens` | ขอ token ตั้งต้น |

`AGENTS.md` ให้เอเจนต์ **อ่าน** หลักการได้ ส่วน MCP ให้มัน **รันเครื่องมือตรวจ** ได้
ซึ่งการอ่านอย่างเดียวทำไม่ได้

มันคืนค่าสิ่งที่เครื่องมือพิมพ์ออกมาตรงๆ พร้อมรหัสจบ: **0** ตรวจแล้วไม่เจออะไร
**1** เจอปัญหา **2** ตรวจไม่ได้ — ซึ่ง 2 ไม่ใช่ผ่าน

## 4. Homebrew — ได้คำสั่งติดเครื่อง

```bash
brew install plugin87/tap/ux-ui-agent-skills
```

บรรทัดเดียวจบ ไม่ต้อง `brew tap` ก่อน และถ้ายังไม่มี Node มันลงให้ด้วย

ได้คำสั่ง 2 ตัวใช้ได้ทุกที่

```bash
ux-ui-skills init          # ลงชุดเครื่องมือในโปรเจกต์
ux-ui-mcp                  # เซิร์ฟเวอร์ MCP ไม่ต้องผ่าน npx
claude mcp add ux-ui-gates -- ux-ui-mcp
brew upgrade ux-ui-agent-skills
```

> **หาด้วย `brew search` ไม่เจอจนกว่าจะติดตั้งครั้งแรก**
> เพราะ `brew.sh` เก็บรายชื่อเฉพาะของที่อยู่ใน homebrew-core ส่วนอันนี้เป็น tap ส่วนตัว
> คำสั่งข้างบนคือทางเข้าทางเดียว เลยต้องแปะไว้ทุกที่ที่พูดถึงโปรเจกต์นี้

## 5. npx — ไม่ติดตั้งอะไรเลย

```bash
npx ux-ui-agent-skills demo        # เปิดตัวอย่างดู
npx ux-ui-agent-skills init        # ลงทั้งชุดในโฟลเดอร์ปัจจุบัน
npx ux-ui-agent-skills new ./app   # สร้างโปรเจกต์ใหม่จากโครงตั้งต้น
npx ux-ui-agent-skills list        # ดูว่ามีอะไรให้บ้าง
```

`demo` เปิดหน้าที่ผ่านเครื่องมือตรวจมาแล้ว ดูเสร็จลบโฟลเดอร์ทิ้งได้ ไม่มีอะไรค้างในเครื่อง

## ของที่ได้เหมือนกันทุกทาง

ส่วนที่ทำงานจริงไม่เคยขึ้นกับว่าเอเจนต์ตัวไหนอ่าน

- **ไฟล์ token 14 ไฟล์** รูปแบบ DTCG — สี ตัวอักษร ระยะห่าง การเคลื่อนไหว ธีม ขนาด กราฟ
- **สเปกคอมโพเนนต์ 52 ชิ้น** พร้อมโครงสร้าง ตัวแปร สถานะทั้ง 8 และ ARIA
- **ดีไซน์ซิสเต็ม 138 ชุด** แต่ละชุดเป็นสเปกเต็ม
- **เครื่องมือตรวจ 52 ตัว** — 34 ตัวเปิดเบราว์เซอร์จริง อีก 18 ตัวอ่านไฟล์

ทั้งหมดเป็น Node กับ Python ธรรมดา ไม่มีตัวไหนรู้ว่าใครเรียกมัน

## เรื่องเบราว์เซอร์ ที่ต้องรู้

เครื่องมือตรวจที่ต้องเปิดหน้าเว็บจริง ต้องลงเบราว์เซอร์ก่อน **ครั้งเดียวต่อเครื่อง**

```bash
npm install && npx playwright install chrome
```

ถ้าไม่ลง มันจะพิมพ์ `SKIPPED` แล้วจบด้วยรหัส 0

**รหัส 0 ตรงนั้นไม่ได้แปลว่าผ่าน** มันแปลว่าไม่ได้วัดอะไรเลย ซึ่งอันตรายกว่า
เพราะหน้าตาเหมือนผ่าน ถ้าจะเชื่อผลลัพธ์ให้ใส่ `DS_REQUIRE_BROWSER=1` นำหน้า
มันจะฟ้องดังๆ แทนที่จะเงียบ

> `node scripts/accuracy_report.mjs` เป็นการทดสอบตัวเอง **ของชุดเครื่องมือ**
> ไม่ใช่ของคุณ มันชี้ไปที่ตัวอย่างในโปรเจกต์ของมันเอง เอาไปรันในโปรเจกต์อื่น
> จะได้คะแนนต่ำ ซึ่งไม่ได้แปลว่าโปรเจกต์คุณแย่ ให้รันเฉพาะในโฟลเดอร์ของชุดเครื่องมือ

## สิ่งที่วัดไม่ได้

เครื่องมือทั้งหมดวัด **ความถูกต้อง** — token คอนทราสต์ การเข้าถึง ความสม่ำเสมอ
มันไม่ได้วัดว่างานสวยหรือดีหรือไม่

สำหรับส่วนที่สคริปต์วัดไม่ได้ มี `/critique` ซึ่งเป็นตัววิจารณ์ที่เปิดดูงานจริง
แล้วพยายามหาเหตุผลที่จะปฏิเสธ พร้อมอ้างหลักฐานทุกข้อ

มันรันแยก context ไม่เห็นเหตุผลที่คนทำใช้ตัดสินใจ เพราะตัววิจารณ์ที่รู้ว่าคนทำคิดอะไร
จะไปวิจารณ์เหตุผล แทนที่จะวิจารณ์ชิ้นงาน

**ไม่มีตัวเลขไหนในโปรเจกต์นี้ที่ครอบคลุมเรื่องรสนิยม** และทุกเครื่องมือที่พิมพ์ตัวเลข
ก็บอกแบบนี้ทุกครั้ง
